# Между нами

Русскоязычный сайт для совместного самоанализа отношений. Один участник создаёт тест и отправляет второму персональную ссылку. Каждый отвечает на 50 вопросов независимо. После двух отправок оба видят разбор девяти общих тем и личную проверку безопасности, сильные стороны, темы для внимания и упражнения для разговора.

Это авторский опрос и прозрачный анализ по правилам, а не валидированный психологический тест. Внешние ИИ API не используются, ответы сторонним сервисам анализа не отправляются.

## Локальный запуск

Нужен Python 3.12+, внешних зависимостей нет:

```sh
cd /workspace/my-proj
python3 server.py
```

Сервер слушает порт 8000. `PORT` меняет порт, `DATA_DIR` — папку базы SQLite (по умолчанию `data/`). Проверка готовности: `curl -fsS http://127.0.0.1:8000/health`. Для доступа из разных городов требуется публикация на общедоступном HTTPS-хостинге; локальный запуск этого не обеспечивает.

```sh
python3 -m unittest discover -s tests -v
```

## Публикация на Render без своего домена

1. Загрузите эти файлы в ваш репозиторий GitHub. Затем на Render создайте **Web Service**, подключив этот репозиторий. Выберите среду **Docker**.
2. Выберите тариф с поддержкой постоянного диска (обычно платный; проверьте текущую стоимость у провайдера). Добавьте **Persistent Disk** с путём `/data`. Не используйте эфемерный диск для реальных ответов: после перезапуска они могут исчезнуть.
3. Добавьте переменную `DATA_DIR=/data`, задайте путь проверки здоровья `/health`. Dockerfile использует `PORT`, предоставляемый хостингом, либо 8000.
4. Запустите развёртывание. Получите публичный адрес HTTPS, который выдаст Render. Свой домен не нужен. Используйте один экземпляр приложения с этим диском: SQLite не предназначен здесь для нескольких реплик.
5. Откройте адрес на первом устройстве, создайте тест и скопируйте приглашение. Откройте приглашение на втором устройстве (например, через мобильный интернет), заполните тест независимо. После второй отправки на обоих устройствах должен появиться общий разбор с одинаковыми общими ответами и отдельным личным блоком безопасности для каждого. Сохраните свою исходную ссылку для возврата.

Развёртывание на Render в этой задаче не выполнено: нужны ваша учётная запись хостинга, подключение GitHub и выбор тарифа. Не передавайте пароли или токены в чат.

Альтернатива на своём сервере с Docker:

```sh
docker build -t couple-test .
docker volume create couple-data
docker run -d --name couple-test --restart unless-stopped -p 8000:8000 -v couple-data:/data couple-test
```

Перед публичным использованием настройте HTTPS через обратный прокси и ограничьте прямой доступ к порту 8000.

В Docker запуск выполняется через `docker_start.py`: он подготавливает права только папки данных и файлов SQLite на подключённом диске, затем запускает приложение с UID/GID 10001 без root. Это позволяет использовать новый постоянный диск без ручного изменения прав. Проверены сборка образа, запуск с подключённым диском, вход по паролю и сохранение сессии после перезапуска контейнера.

## Формат и анализ

Перед началом каждый выбирает подпись «Он» или «Она», а по желанию — имя или псевдоним и знак зодиака. Выбор не меняет вопросы и не подразумевает противоположный пол второго участника.

Оба получают одинаковые 50 вопросов, по одному на экране: короткие истории, выбор нескольких пунктов, шкалы «что тебе ближе» от 1 до 7, блиц «мне ок / не ок / зависит», да/нет, «кто», число и время. Имя или псевдоним необязательны, знак зодиака — только для развлечения. Даты рождения и почта не собираются. Любой вопрос можно пропустить. Ноль и середина шкалы — настоящие ответы. Открытые ответы ограничены 1500 символами. Исключающие варианты вроде «Меня всё устраивает» нельзя совмещать с другими пунктами.

Первые 45 вопросов — девять тем: ваша история, честно о вас, что вам важно, ссоры и общение, что тебе ближе, ваши ожидания, тебе это ок, договоримся на берегу, зелёные флаги. После двух отправок оба видят эти ответы, включая свободный текст. Личные ответы о безопасности недоступны партнёру.

Визуальный формат и разнообразие вопросов вдохновлены предоставленными пользователем скриншотами sovmestimost.love. Это самостоятельная реализация под названием «Между нами», не копия исходного сервиса. Вопросы адаптированы, логотип и иллюстрации источника не используются. Личные ответы пользователя со скриншотов не сохранялись в приложении и не использовались как демонстрационные данные. Скриншотов исходного отчёта не было: алгоритм и структура анализа разработаны для этого приложения, методика источника неизвестна.

Отчёт содержит общие желания и сильные стороны, различия ожиданий, тёплые цитаты без смысловой интерпретации, отдельное сопоставление своего поведения в ссоре со взглядом партнёра и план небольших действий. «Близкий ответ» — одинаковый ответ на сопоставимый закрытый вопрос или разница не больше 1 по шкале 1–7; разница от 3 выделяется как заметное различие предпочтений. Пропуски, неопределённость, тексты и множественный выбор не входят в счёт совпадений. Общие пункты множественного выбора выводятся отдельно, без превращения в баллы совместимости. Неотмеченный пункт не считается отрицанием. Предпочтения не получают оценки «хорошо/плохо». Для вопроса «кто» учитывается позиция отвечающего. В описании ссор сопоставляются самоотчёт одного и описание того же человека вторым.

Зелёные флаги берутся из совместно выбранных сильных сторон и двух «да» в пяти специальных вопросах. При хотя бы одном «нет» вопрос отмечается как потребность в разговоре. План действий выбирается по общим пожеланиям и расхождениям. Свободный текст показан в цитатах и полном списке ответов; автоматическая смысловая психологическая интерпретация не выполняется. Общий процент совместимости, типы привязанности и диагнозы не рассчитываются.

Последние пять вопросов — личная проверка унижения, контроля, угроз, сексуального давления и физической агрессии. Ответы и персональные сигналы получает только отвечающий по своей ссылке, включая этап ожидания второго участника. Второму они не передаются API и не входят в общий анализ. Ответ «да» обозначает описанное поведение по самоотчёту, а не доказывает факты или устанавливает, «кто абьюзер». Пропуск и отсутствие отмеченных сигналов не доказывают безопасность.

«Кто ангел» — шуточное перечисление положительных сигналов, которые в отношениях с человеком отметил его партнёр, без рейтинга людей. Гороскоп — отдельный развлекательный текст по выбранным знакам, без научных претензий и влияния на анализ. Красные флаги не компенсируются зелёными и не участвуют в развлечениях.

Полный список: [QUESTIONNAIRE.md](QUESTIONNAIRE.md). Источник формулировок и типов полей: `questions.json`. При изменении несовместимой схемы ответов увеличивайте VERSION в server.py: старые сессии не должны трактоваться по новым правилам. Прежние сессии можно удалить; для нового теста создайте новую ссылку.

## Полный отчёт без оплаты

Отчёт расширен по предоставленным пользователем скриншотам. Все 16 разделов доступны сразу: портрет, шуточное звание, 12 тематических карточек, все границы, флагометр, личная безопасность, шесть игровых номинаций, десять сравнений ожиданий, приоритетный разговор с заданием на вечер, до трёх сильных и слабых сторон, раздражающие привычки и просьбы, тёплые слова, близость и договорённости о верности, пять свиданий, шесть сценариев для обсуждения, фильм и мем пары. При недостатке данных вывод не подменяется догадкой.

Скрытые тексты и платная методика стороннего сервиса неизвестны и не восстанавливались. Содержание разработано самостоятельно в `report.py`; модуль получает **только первые 45 общих ответов**. Отрисовка — `public/report.js`. Источники выводов помечаются номерами вопросов. Личные ответы 46–50 доступны только своему участнику через существующий блок безопасности.

Круговой процент в начале — доля близких ответов среди сопоставимых закрытых вопросов, а не совместимость. Четыре дополнительных процента показывают наблюдаемые доли: разных сопоставимых ответов, заметных различий на шкалах, разных взглядов на границы и ответов «Нет» среди определённых ответов о зелёных флагах. Формула всегда `числитель / знаменатель × 100`, округление до целого. При нулевом знаменателе — прочерк. Это **не вероятности** ссоры, измены или расставания. Данные о личной безопасности и знаки зодиака на эти проценты не влияют.

Раздел «Кто в паре абьюзер?» сохраняет вопрос как заголовок, но не назначает человеку ярлык. Публичные сигналы имеют авторство и основания: например, повышение голоса в самоотчёте, оценка партнёра или отношение к просмотру телефона без разрешения. Допустимость поступка не доказывает его совершение. Личные сигналы угроз, давления и насилия не участвуют в публичном рейтинге. Шуточные номинации выводятся только из явно выбранных предпочтений, а не из анализа силы любви или мудрости.

Ответы каждого выделены своим цветом и подписью А/Б. Сопоставимые совпадения и различия дополнены текстовыми метками; цвет не является единственным носителем смысла. Открытый текст показан без изменения и без психологической интерпретации.

Кнопка сохранения PDF вызывает системную печать. При печати раскрываются детали общего отчёта и скрывается весь личный раздел №6. После печати состояние раскрытия восстанавливается. В браузерном тесте проверяются это исключение, все разделы, числа, подсветка и доступность с двух устройств. Для конфиденциальности при передаче PDF проверьте колонтитулы браузера: не включайте в них свою личную ссылку.

## Сохранение ответов для отдельного разбора

На странице результата есть блок скачивания:

- **Общие ответы пары · TXT** — читаемый файл с 45 вопросами и 90 ответами, подписями обоих участников и вариантами ответов.
- **Общие ответы пары · JSON** — те же исходные данные в структурированном виде, включая версию анкеты, типы полей, диапазоны шкал и отметки пропусков.
- **Все мои 50 ответов · личный TXT** — только ответы текущего участника, включая пять личных вопросов. Доступен сразу после собственной отправки, даже если второй ещё не закончил.

Для анализа всех 100 ответов каждый добровольно скачивает собственный личный файл; эти два файла можно прикрепить в чат. Для анализа без личных вопросов достаточно общего TXT или JSON. Исходный текст, переносы строк, кириллица, нули и множественный выбор сохраняются. Пропуск записывается явно, в JSON это `skipped: true` и `value: null`. Личные ссылки, идентификаторы сессии и токены автоматически не включаются.

Авторизация и срок хранения проверяются при каждом запросе `/api/export`. Общая выгрузка недоступна до двух отправок и никогда не содержит личные вопросы. Выгрузка личных ответов не возвращает чужой профиль и чужие ответы. После удаления или истечения срока сессии новые выгрузки недоступны. Уже скачанные файлы остаются на устройстве владельца и не удаляются вместе с серверной сессией. Импорт ответов и восстановление черновика из файла не реализованы.

Проверка реальных скачиваний в Chromium: `node tests/export-browser.cjs` при работающем сервере. Проверяются оба участника, TXT/JSON, сохранность текста и типов, собственные 50 ответов до завершения пары, запрет ранней общей выгрузки, приватность и отсутствие автоматического включения токенов.

## Вход только для вас двоих

Необязательная секретная переменная `SITE_PASSWORD` включает общий вход HTTP Basic для страницы, файлов приложения и всех API. Логин — `para`, пароль задаётся в настройках хостинга. Используйте публичный HTTPS-адрес. При отсутствии или пустом значении переменной этот слой защиты выключен. Общий пароль не заменяет личные ссылки участников и не ограничивает число людей: доступен всем, кто знает пароль. Не помещайте пароль в URL или репозиторий. Для смены пароля обновите переменную и перезапустите сервис.

Проверка здоровья `/health` остаётся без пароля и возвращает только `{"ok": true}` для мониторинга хостинга, без данных пары. Приложение не журналирует заголовки авторизации. Тесты проверяют доступ к странице, файлам и API, неверные и повреждённые заголовки, а также работу двух браузеров с общим паролем. `node tests/access-browser.cjs` поднимает отдельный временный сервер и очищает его после проверки.

## Приватность и ограничения

- Имена, почта и регистрация не нужны. Личные ссылки являются ключами доступа, в том числе к личным сигналам безопасности. Не публикуйте их. Люди с доступом к устройству или личной ссылке могут увидеть личный результат.
- Токены находятся во фрагменте URL, не передаются серверу при загрузке страницы и не записываются приложением в журналы запросов. API получает их в теле POST-запроса.
- Ответы сохраняются в SQLite на сервере в открытом виде. Администратор хостинга имеет к ним доступ. Для резервных копий нужен отдельный порядок хранения и удаления.
- Общие ответы 1–45 открываются обоим только после двух заполнений. Исправление отправленных ответов не предусмотрено; можно удалить сессию и создать новую.
- Сессия становится недоступной через 30 дней. Физическое удаление просроченных строк выполняется при следующем POST-запросе; резервные копии и освобождение страниц SQLite требуют отдельной политики оператора.
- Любой из двух участников может удалить сессию целиком. Удаление делает обе ссылки недействительными.
- Черновик ответов хранится только в памяти вкладки до отправки и теряется при её обновлении.
- Это небольшое приложение для личного использования. Перед массовым публичным запуском нужны ограничение частоты запросов на прокси, мониторинг, резервирование и юридические тексты под вашу юрисдикцию.

## Дополнительная браузерная проверка

При наличии Playwright и Chromium: `node tests/browser.cjs`. Запустите сервер отдельно. По умолчанию тест использует локальный порт 8000 и `/usr/bin/chromium`; переменные `TEST_BASE_URL` и `CHROMIUM_PATH` переопределяют их. Проверяются оба участника, разные типы ответов, приватность последнего блока, экранирование свободного текста, гороскоп и мобильная ширина. Используются только искусственные ответы.
