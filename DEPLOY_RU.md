# Запуск «Между нами»: GitHub → Render

## Что в этой версии

Сайт готов к публикации: 50 одинаковых вопросов для обоих, прохождение с разных устройств, общий отчёт из 16 разделов, подсветка ответов, PDF и личный блок безопасности. Ответы сохраняются в SQLite на постоянном диске.

**Нейросеть пока не подключена.** Анализ строится локально по правилам и шаблонам в `server.py` и `report.py`. Сами ответы пары не отправляются в ИИ. Добавление API-ключа в настройки этой версии само по себе ничего не подключит: сначала нужна реализация вызова ИИ и согласия на передачу ответов. Подписка на ChatGPT не заменяет доступ к API; использование API оплачивается отдельно.

Ниже — запуск именно текущей версии. Публичного адреса пока нет.

## 1. Скачай и распакуй архив

Распакуй `mezhdu-nami-site.zip` на компьютере. Внутри должны лежать `Dockerfile`, `docker_start.py`, `server.py`, `report.py`, `questions.json`, папка `public` и другие файлы проекта. Тестовых ответов, базы данных, токенов и папки `.git` в архиве нет.

## 2. Открой свой репозиторий GitHub

Открой https://github.com/zarunast/my-proj и войди в свой аккаунт.

- Если репозиторий пустой, выбери ссылку **uploading an existing file**.
- Если файлы уже есть, выбери **Add file → Upload files**.

Перетащи **содержимое** распакованной папки: все файлы и папки, а не ZIP и не внешнюю папку целиком. `Dockerfile` должен оказаться прямо в корне репозитория, а `app.js`, `report.js`, `style.css` и `index.html` — внутри `public/`.

Нажми **Commit changes**. Если GitHub предлагает имя первой ветки, выбери `main`.

## 3. Создай сервис на Render

1. Открой https://render.com и войди через GitHub.
2. Выбери **New → Web Service**.
3. Подключи GitHub, разрешив доступ к `zarunast/my-proj`.
4. Выбери этот репозиторий и ветку `main`.

Названия элементов интерфейса могут немного отличаться.

## 4. Задай параметры

| Настройка | Значение |
| --- | --- |
| Name | Любое свободное имя, например `mezhdu-nami` |
| Branch | `main` |
| Runtime / Language | **Docker** |
| Root Directory | Оставить пустым |
| Dockerfile Path, если поле есть | `./Dockerfile` |
| Health Check Path | `/health` |

Команды установки Python-пакетов не нужны: приложение использует стандартную библиотеку. Команда запуска уже указана в `Dockerfile`.

## 5. Подключи постоянный диск

Для этой версии нужен тариф с поддержкой **Persistent Disk**. Проверь актуальную стоимость у Render перед подтверждением оплаты: бесплатный временный диск не подходит для надёжного хранения ответов.

В разделе **Disks / Add Disk** укажи:

- Имя: `couple-data`.
- Mount Path: `/data`.
- Размер: минимальный доступный, для личного использования достаточно 1 GB.

Используй **один экземпляр** приложения. Эта конфигурация SQLite не рассчитана на несколько независимых реплик.

## 6. Включи вход по паролю

В разделе **Environment** добавь:

```text
DATA_DIR=/data
SITE_PASSWORD=придумай_длинный_общий_пароль
```

Значение `SITE_PASSWORD` — твой собственный пароль, а не буквальный пример выше. Задай его как секретную переменную в настройках Render. Не добавляй пароль в GitHub или в файлы проекта. Без этой переменной защита сайта выключена. Логин фиксированный: `para`.

Если Render сам задаёт `PORT`, оставь его значение. Иначе Dockerfile использует порт 8000. Для нынешнего анализа API-ключи не нужны.

## 7. Запусти публикацию

Нажми **Create Web Service / Deploy**. Дождись состояния **Live**. Если возникнет ошибка, открой **Logs** и сохрани текст ошибки без секретов — по нему можно определить причину.

Render выдаст публичный HTTPS-адрес. Используй именно его. Свой домен покупать необязательно.

## 8. Проверь сайт

1. Открой выданный HTTPS-адрес. Браузер должен попросить логин и пароль: логин `para`, пароль — значение, которое ты задала в `SITE_PASSWORD`. Затем появится страница «Между нами». Проверь тот же адрес в режиме инкогнито: без пароля он не должен открываться.
2. Добавь к адресу `/health`. Ожидаемый ответ: `{"ok": true}`.
3. Вернись на главную, подтверди согласие и создай тест.
4. Сохрани свою ссылку из адресной строки.
5. Скопируй **ссылку для партнёра** и отправь ему.
6. Каждый выбирает «Он/Она» и отвечает на своём устройстве.
7. После двух отправок должен появиться общий отчёт. Личные ответы о безопасности у каждого свои.
8. Для проверки постоянного хранения перезапусти сервис в Render и открой сохранённые ссылки: ответы должны остаться.

Передай партнёру общий пароль отдельно от личных ссылок. У него при первом открытии тоже появится запрос логина `para` и пароля. Доступ получит любой, кому вы передадите пароль; привязки к двум конкретным людям или устройствам нет. Не включай пароль в адрес сайта. Смена `SITE_PASSWORD` и перезапуск сервиса меняют общий пароль, но не удаляют ответы.

Отправляй партнёру приглашение, а не собственную ссылку: личная ссылка даёт доступ к твоему приватному результату.

## Как прислать ответы на разбор

После двух заполнений нажми **Общие ответы пары · TXT**. Скачанный файл можно прикрепить в чат — в нём будут вопросы 1–45 и ответы обоих.

Если хотите разбор всех 100 ответов, каждый со своего устройства скачивает **Все мои 50 ответов · личный TXT**. Пришлите два этих файла только с добровольного согласия обоих. В личном файле есть ответы о безопасности; общий файл их не содержит. Можно ограничиться общим файлом.

## 9. Если нужна настоящая нейросеть

До утверждения, что отчёт создаёт ИИ, нужно отдельно:

1. Выбрать поставщика и модель API.
2. Реализовать серверный запрос к модели, ограничения объёма, обработку ошибок и проверку формата ответа.
3. Добавить явное согласие обоих участников на передачу общих ответов стороннему ИИ. Личные пять ответов о безопасности не передавать.
4. Разместить ключ только в секретных настройках хостинга, не в GitHub, браузере или переписке.
5. Проверить реальный вызов модели и работу при сбоях. Результат без вызова ИИ помечать как локальный разбор, а не нейросетевой.

Даже ИИ не может достоверно вычислить вероятность расставания или установить, кто абьюзер, по такой анкете. Числа в текущем отчёте — объяснимые доли ответов.
